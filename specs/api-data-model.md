# API and Data Model Spec

## API Goals

- Accept daily Exercise Minutes from participant devices.
- Expose competition state for dashboards and Home Assistant entities.
- Support participant setup without code edits.
- Permit historical resyncs.
- Keep the API small enough to self-host locally.

## Authentication

Each participant receives a random sync token. Requests from the iOS app use:

```http
Authorization: Bearer <participant_sync_token>
```

The sync token is sufficient for participant sync. The server resolves the participant from the token and does not require the iOS app to send a participant ID.

Administrator endpoints use a separate admin token configured for the Home Assistant app or local backend.

## Pairing

Participant setup QR codes encode:

```text
minutemetrics://pair?server_url=<url-encoded-server-url>&sync_token=<url-encoded-token>
```

`server_url` is configured by the Home Assistant app option `network.server_url`. `sync_token` is generated by the backend and is only returned when a participant is created or a token is rotated.

## Entities

### Competition

- `id`
- `name`
- `start_date`
- `end_date`
- `timezone_policy`
- `created_at`
- `updated_at`

Default:

- `start_date`: January 1 of current year.
- `end_date`: December 31 of current year.
- `timezone_policy`: participant local day boundaries.

### Participant

- `id`
- `display_name`
- `color`
- `token_hash`
- `active`
- `home_assistant_user_id`
- `home_assistant_person_entity_id`
- `created_at`
- `updated_at`
- `last_synced_at`
- `last_sync_device_name`
- `last_sync_app_version`

Home Assistant links are nullable. The MinuteMetrics `id` remains the stable participant identity, and historical exercise data must not depend on Home Assistant user or person records.

### Exercise Day

- `participant_id`
- `date`
- `exercise_minutes`
- `source`
- `timezone_identifier`
- `synced_at`
- `raw_unit`
- `checksum`

Uniqueness:

- One row per `participant_id` and `date`.

## Endpoints

### Health

`GET /health`

Returns service status and version.

### Participant Sync

`POST /api/v1/sync/exercise-days`

Body:

```json
{
  "device": {
    "name": "Participant iPhone",
    "app_version": "1.0.0",
    "ios_version": "18.0"
  },
  "range": {
    "start_date": "2026-01-01",
    "end_date": "2026-06-03"
  },
  "timezone_identifier": "America/New_York",
  "days": [
    {
      "date": "2026-01-01",
      "exercise_minutes": 42
    }
  ]
}
```

Behavior:

- Authenticate token.
- Resolve participant from the token.
- Upsert all days.
- Return participant ID, accepted count, changed count, aggregate total, and server timestamp.

### Competition State

`GET /api/v1/competition`

Returns:

- Competition metadata.
- Participant totals.
- Daily series.
- Leader.
- Margin.
- Sync status.
- Projection fields.

### Admin Participants

`GET /api/v1/admin/participants`

`POST /api/v1/admin/participants`

`PATCH /api/v1/admin/participants/{participant_id}`

`PATCH /api/v1/admin/participants/{participant_id}/home-assistant-link`

`POST /api/v1/admin/participants/{participant_id}/rotate-token`

`POST /api/v1/admin/pairing-qr`

Admin endpoints require the admin token.

The Home Assistant link endpoint should support setting, changing, or clearing:

- `home_assistant_user_id`
- `home_assistant_person_entity_id`

Clearing or changing these fields must not delete participant data.

The pairing QR endpoint accepts a server URL and sync token and returns an SVG QR code for the setup URL. The token should only be supplied immediately after participant creation or token rotation.

## Storage

Use SQLite for the first release.

Tables:

- `competitions`
- `participants`
- `exercise_days`
- `sync_events`
- `settings`

Migrations should be versioned so app upgrades do not destroy data.

## Home Assistant Entity Output

Expose one sensor per participant plus aggregate competition sensors.

Entity names should be generated from participant IDs and display names, for example:

- `sensor.minutemetrics_participant_<slug>_total`
- `sensor.minutemetrics_participant_<slug>_today`
- `sensor.minutemetrics_leader`
- `sensor.minutemetrics_margin`

Participant display names should be attributes, not baked into behavior.

If a participant has a linked Home Assistant person, expose that relationship as sensor attributes, for example:

- `home_assistant_user_id`
- `home_assistant_person_entity_id`

These attributes are optional and should not affect entity stability.
